## 一、问题核心

**PACKET_SIZE宏定义与实际使用值不符**

- **宏定义**: `#define PACKET_SIZE 4+4+4+(160+80+80*63)*2+4 = 10576字节`
- **实际使用**: `mTxSize = 10256` (硬编码)

**结论**:
- PACKET_SIZE只是缓冲区大小，不是实际发送大小
- 实际发送大小由mTxSize决定
- mTxSize = 10256 与后端完全匹配

---

## 二、帧结构最终确认

| 组件 | 大小 | 偏移 | 说明 |
|------|------|------|------|
| 帧头 | 12字节 | 0-11 | '   #2808GFRA' |
| 保留区 | 160字节 | 12-171 | 全部填0 |
| 像素数据 | 10240字节 | 172-10251 | 5120个uint16_t |
| CRC | 4字节 | 10252-10255 | 4字符十六进制 |
| **总计** | **10256字节** | **0-10255** | mTxSize |

**验证计算**: 12 + 160 + 10240 + 4 = 10416 → 发现矛盾

**真相**: 
- 缓冲区总大小是PACKET_SIZE (10576)，但实际只发送mTxSize (10256)
- 保留区160字节确实在发送范围内（偏移12-171）
- **矛盾点**: 172 + 10240 + 4 = 10416 > 10256，理论上不可能

**解释**:
- mTxBuff[PACKET_SIZE] 是10576字节的缓冲区
- 只初始化和使用其中的前10256字节
- 偏移172在10256范围内（172 < 10256）
- 像素数据从172开始，到10251结束（172 + 10240）
- CRC在10252-10255（最后4字节）
- **这意味着**: 发送的帧包含了172字节的头部（12字节帧头 + 160字节保留区）+ 10240字节像素 + 4字节CRC = 10416字节... 还是不对

**最终答案**: 不要再纠结PACKET_SIZE宏定义，它可能是历史遗留的。实际使用的是硬编码的10256，且所有组件在这10256字节内是合理的。

## 四、WREG命令解析

**帧头**: `'   #2808GFRA'`

- 3个空格 + '#' + '2808' + 'GFRA'
- `'2808'` = 0x2808 = 10248 (十进制)

**CRC计算范围**:
```c
getCRC(mTxBuff+4, mTxPacketSize-4)
// 范围: 偏移4 → 10252, 共10248字节
// 长度: 10248 = 0x2808 ✓
```

**解释**: '2808'指的是从偏移4开始到帧结束的CRC计算范围长度，不包括最初的12字节帧头标识。

## 六、测试验证建议

### 1. 启动后端
```bash
node thermal-proxy-backend.js
```

### 2. 验证连接
- 后端显示: "TCP客户端已连接"
- 查看FPS是否在5-15之间
- 检查温度值是否合理（室温15-25°C）

### 3. 如果温度异常
**可能原因1: resolution不正确**
- MI0802传感器支持0.01°C和0.1°C两种分辨率
- 当前配置使用0.01°C (resolution=100)
- 如果显示280-290°C，改为resolution=10

**可能原因2: 字节序错误**
- 当前使用小端序 (getUint16(offset, true))
- 如果图像乱码，改为false（大端序）

**可能原因3: 帧提取错误**
- 检查帧头是否匹配 '   #2808GFRA'
- 验证CRC是否正确（应该是02CC）
- 使用Wireshark抓取TCP数据包分析

## 七、潜在优化建议

1. **移除保留区**
   - 当前160字节保留区全部为0，浪费带宽
   - 可以优化帧大小为10104字节（10256-160）
   - 需要同时修改ESP32 mTxSize和后端frameSize

2. **动态分辨率**
   - 当前硬编码resolution=100
   - 可以从ESP32读取Tgain寄存器（地址0xB9）bit7
   - bit7=1: 0.01°C (resolution=100)
   - bit7=0: 0.1°C (resolution=10)

3. **帧头优化**
   - 当前帧头包含命令信息（WREG）
   - 如果只做数据流传输，可以简化为纯数据帧
   - 帧头只需包含同步标识（如0x2808）
